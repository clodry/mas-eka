# Мастерская ЕКА — сайт строительной компании

Одностраничный сайт (Главная / О нас / Блог) на Node.js + Express + PostgreSQL,
со встроенной админ-панелью для управления постами блога (создание,
редактирование, удаление).

## Что внутри

- `server.js` — точка входа Express-сервера
- `db/database.js` — подключение к PostgreSQL (`pg`), создание схемы при
  первом запуске и посев демо-постов
- `routes/` — API: `/api/auth/*` (вход/выход) и `/api/posts/*` (CRUD постов)
- `middleware/` — `requireAuth.js` (защита CRUD-эндпоинтов), `rateLimit.js`
  (ограничение попыток входа), `verifyOrigin.js` (защита от CSRF)
- `utils/` — общие помощники: `uploads.js` (безопасные имена и пути файлов),
  `config.js` (флаги окружения), `slugify.js`, `siteUrl.js`, `analytics.js`
- `views/` — разметка админ-панели (`admin.html`, `admin-login.html`). Лежит
  отдельно от `public/` намеренно: файлы из `public/` express отдаёт статикой
  кому угодно, а панель должна открываться только по сессии
- `public/` — публичная вёрстка: `index.html`, `blog.html`, `404.html`, стили, скрипты
- `public/uploads/` — сюда сохраняются загруженные через админку изображения постов

## Запуск локально

Требуется Node.js 18+ и доступ к PostgreSQL (локальный или облачный).

```bash
npm install
cp .env.example .env
```

Заполните в `.env` как минимум `DATABASE_URL` (строка подключения к вашей
базе Postgres), `SESSION_SECRET` и `ADMIN_PASSWORD_HASH` — см. комментарии
в `.env.example`. База данных и таблицы создаются автоматически при первом
запуске сервера (`node server.js`) — ничего руками накатывать не нужно.

Если PostgreSQL ещё не установлен локально:

```bash
# Ubuntu/Debian
sudo apt-get install postgresql
sudo -u postgres createdb mas_eka
# DATABASE_URL=postgresql://postgres:ВАШ_ПАРОЛЬ@localhost:5432/mas_eka
```

Откройте `.env` и задайте:

1. `SESSION_SECRET` — длинная случайная строка (для подписи cookie), минимум
   16 символов. Сгенерировать:

   ```bash
   node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
   ```

2. `ADMIN_LOGIN` — логин администратора блога (по умолчанию `admin`).
3. `ADMIN_PASSWORD_HASH` — bcrypt-хэш пароля. Получить его:

   ```bash
   npm run hash-password -- "ваш-пароль"
   ```

   Скопируйте полученную строку в `ADMIN_PASSWORD_HASH`.

При `NODE_ENV=production` приложение не запустится, если `SESSION_SECRET` или
`ADMIN_PASSWORD_HASH` не заданы — это защита от случайного выката с пустыми
секретами. В режиме разработки оно стартует с временным секретом и предупреждением.

Запустите сервер:

```bash
npm start
```

Сайт откроется на `http://localhost:3000`:

- `/` — главная страница
- `/blog` — блог (список статей + просмотр)
- `/admin` — панель управления (без сессии редиректит на `/admin/auth` — форму входа)

## Как устроена админка

- `/admin/auth` показывает форму входа. После успешного логина (проверяется
  на сервере через bcrypt + сессию с httpOnly-cookie) открывается панель.
- Слева — форма создания/редактирования поста (заголовок, анонс, текст,
  необязательное изображение).
- Справа — список всех постов с кнопками «Редактировать» и «Удалить».
- Все создающие/изменяющие запросы (`POST`, `PUT`, `DELETE` к `/api/posts`)
  защищены middleware `requireAuth` и без сессии администратора вернут 401.
- Сама разметка панели (`views/admin.html`), а также `/js/admin.js` и
  `/css/admin.css` без сессии не отдаются — на них приходит 404.
- После 10 неудачных попыток входа с одного IP форма входа блокируется на
  15 минут (успешный вход сбрасывает счётчик). Если администратор сам себя
  заблокировал, ждать необязательно — счётчик живёт в памяти процесса и
  сбрасывается перезапуском сервера.

## Оформление

Стиль — «архитектурное бюро»: белая база, крупная спокойная типографика
(Manrope в заголовках, Inter в тексте), один акцентный цвет `--accent`,
тонкие линии вместо рамок и теней. Декоративных эффектов нет намеренно —
кастомный курсор, плёночное зерно, чертёжная сетка, контурные водяные
знаки и бегущая строка убраны как задававшие прежний «техно»-характер.
Вся палитра, шрифты и радиусы вынесены в переменные в начале
`public/css/style.css` — менять оформление удобнее оттуда.

## Замена плейсхолдер-контента

Сайт собран с демо-текстами, чтобы не блокироваться на реальном контенте.
Перед запуском в продакшн замените:

- **Фон первого экрана — заглушка, замените в первую очередь.** Сейчас
  стоит `public/img/1611724480_jekspertiza-3.jpg`: это единственная
  фотография объекта в проекте, и она всего 512&nbsp;px по ширине, поэтому
  на весь экран растягивается мягко. Нужен горизонтальный снимок от
  1920&nbsp;px. Меняется без правки кода: «Настройки сайта» → «Фон первого
  экрана». Текст героя лежит в левом нижнем углу и подсвечен светлым клином
  (`.hero-scrim`), поэтому главное в кадре держите справа; вуаль вытягивает
  контраст и со светлыми, и с тёмными фото. Права на снимок — на вашей
  стороне: своя съёмка либо лицензия, разрешающая коммерческое
  использование.
- Тексты в `public/index.html` (герой, «О нас», контакты в футере)
- Демо-посты — их можно просто удалить через админку и создать реальные
- Фавикон — сейчас это SVG-заглушка с буквой «E», вшитая в `<head>` страниц
  (см. `<link rel="icon">` в `public/index.html` и в шаблонах `routes/seo.js`)
- Контакты в футере (`public/index.html`) и в `<title>`/`<meta description>`

## SEO

- На главной и в блоге — meta description, Open Graph и Twitter Card.
- `GET /sitemap.xml` — карта сайта с постами (обновляется автоматически).
- `GET /robots.txt` — закрывает `/admin/` и `/api/` от индексации.
- Статьи доступны по ЧПУ `/blog/:slug` с серверным HTML (title, описание,
  og:image, JSON-LD Article) — поисковики и соцсети видят контент без JS.
- Старые ссылки `/blog.html?post=slug` перенаправляются на `/blog/slug` (301).

Перед деплоем задайте `SITE_URL=https://ваш-домен.ru` в `.env` — иначе
sitemap и абсолютные og:url соберутся из заголовков запроса.

## Деплой

Проект — обычное Node.js-приложение, подходит для большинства хостингов
(VPS, Render, Railway, timeweb.cloud и т.п.):

1. Загрузите проект на сервер, выполните `npm install --production`.
2. Создайте `.env` с реальными значениями (см. выше). **Не используйте
   значение `SESSION_SECRET` и пароль по умолчанию.**
3. Задайте `NODE_ENV=production` — тогда cookie получают флаг `Secure`,
   добавляется заголовок HSTS, а запуск без секретов запрещён.
4. Задайте `SITE_URL=https://ваш-домен.ru` — от него зависят sitemap,
   canonical, og:url и проверка источника запросов.
5. Запустите через процесс-менеджер, например `pm2 start server.js --name masterskaya-eka`.
6. Настройте reverse-proxy (nginx) с HTTPS перед Node-приложением.
   Приложение доверяет одному прокси (`trust proxy = 1`) — не ставьте
   перед ним цепочку из нескольких прокси, не поправив это значение,
   иначе ограничение попыток входа будет считать всех за один IP.
7. Убедитесь, что папки `db/` и `public/uploads/` доступны для записи
   процессу Node — там хранятся база данных и загруженные изображения.
   Делайте их регулярный бэкап.

### Что уже сделано для безопасности

- Вход: пароль хранится только как bcrypt-хэш; не больше 10 попыток с
  одного IP за 15 минут; ответ на неверный логин и на неверный пароль
  одинаков и занимает одинаковое время; после входа идентификатор сессии
  перевыпускается (защита от фиксации сессии).
- Сессия: cookie `httpOnly`, `SameSite=Lax`, `Secure` в продакшене.
  Изменяющие запросы принимаются только со страниц самого сайта
  (проверка `Origin`/`Referer` в `middleware/verifyOrigin.js`).
- Админка: и страницы `/admin*`, и её скрипт со стилями отдаются только
  по сессии; в `public/` разметки панели больше нет.
- Загрузки: расширение файла берётся только из белого списка
  (`.jpg/.jpeg/.png/.gif/.webp/.avif`, шрифты `.ttf/.otf/.woff/.woff2`),
  имя файла придумывает сервер. `.svg` и `.html` не принимаются — они
  исполнялись бы браузером с нашего же домена.
- Пути: ссылка вида `/uploads/../../file` больше не проходит проверку,
  так что удалить файл за пределами папки загрузок нельзя.
- Ошибки: наружу уходит либо понятное сообщение (слишком большой файл,
  неверный формат), либо обезличенная 500; подробности — только в лог.
- Заголовки: `nosniff`, `X-Frame-Options`, `Referrer-Policy`,
  `Cross-Origin-Opener-Policy`, HSTS в продакшене.

### Что стоит сделать дополнительно

- Ограничить доступ к `/admin` по IP на уровне nginx, если панель не
  должна быть доступна из интернета всем подряд.
- Content-Security-Policy намеренно не выставляется: в `<head>` страниц
  вставляется готовый код счётчиков (Яндекс.Метрика / GA) из настроек
  сайта, и строгая политика его сломала бы. Если счётчики не нужны —
  добавьте CSP в блок защитных заголовков в `server.js`.
- Поля с кодом счётчиков в «Настройках сайта» — это по смыслу вставка
  произвольного скрипта на сайт. Они доступны только администратору,
  но означают, что доступ в панель равнозначен полному контролю над
  публичными страницами; пароль администратора стоит беречь как ключ
  от сайта целиком.
- Сессии и счётчик попыток входа хранятся в памяти процесса. Для одного
  администратора и одного инстанса это нормально (при перезапуске просто
  придётся войти заново), но express-session предупреждает об этом в логе.
  Если приложение будет работать в нескольких процессах — понадобится
  общее хранилище сессий и ограничение попыток входа на уровне nginx.

## Перенос данных со старой версии на SQLite

Если вы обновляете уже работающий сайт (у него есть файл `db/data.sqlite`
с реальными постами/авторами), перенесите его данные в Postgres одним
разовым скриптом:

```bash
npm install better-sqlite3 --no-save   # временно, только для скрипта
node server.js &   # один раз запустить, чтобы Postgres создал таблицы, затем Ctrl+C
node scripts/migrate-sqlite-to-postgres.js db/data.sqlite
npm uninstall better-sqlite3
```

После успешного переноса проверьте данные и удалите `db/data.sqlite*` —
они больше не используются. Учтите: при первом запуске `node server.js`
создаёт 3 демо-поста (если база была пустой) — после переноса реальных
данных удалите их через админ-панель, они не нужны.

## Технологии

- Express 4, pg (PostgreSQL)
- express-session (cookie-сессии), bcryptjs (хэш пароля)
- multer (загрузка изображений к постам)
- Ванильный HTML/CSS/JS на фронтенде, без сборщиков — можно редактировать
  файлы в `public/` напрямую
